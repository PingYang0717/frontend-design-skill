# 介面文案(i18n)

所有介面文案放在自建的 typed 字典,即使專案只有一種語言也一樣。決策背景見
[ADR-0010](../adr/0010-ui-copy-in-typed-dictionary.md)。

## 1. 字典結構

**規則:**

- [`src/i18n/zhTW.ts`](../../src/i18n/zhTW.ts) 是繁體中文文案,也是**形狀的來源**:
  `export type Translations = typeof zhTW`。
- 其他語言(`src/i18n/en.ts`)宣告成 `const en: Translations`,少一條、多一條、型別不同都編譯失敗。
- 巢狀物件,依用途分組:`app`、`nav`、`common`、`header`、`errors`、`pages.<頁面>`、
  `<domain>`(如 `items`)。沒有字串 key。
- 元件以 `t.items.create.title` 這種屬性存取,全程自動完成。

**原因:** 漏翻是編譯錯誤,而不是執行期才看到的 missing-key;改名時每個呼叫點都會報錯。
複數規則、命名空間、按需載入這些 i18n 函式庫的功能用不到,不引入。

✅ 正確

```ts
export const zhTW = {
  items: {
    title: '項目管理',
    create: { title: '新增項目', nameLabel: '名稱', success: '已新增項目' },
  },
};
```

❌ 錯誤

```ts
t('items.create.title'); // 字串 key:打錯字要到執行期才知道
const LABELS = { create: '新增' }; // 元件自己的文案表,繞過字典
```

- 通用動詞(新增、刪除、取消、重試)放 `common`,不要每個 domain 各寫一次。
- 列舉值的顯示文字用 `satisfies Record<…>` 確保涵蓋,例如
  `status: { … } satisfies Record<ItemStatus, string>`。

## 2. 帶變數的條目寫成函式

**規則:** 需要插入變數的文案寫成函式,參數標型別;不用 `{name}` 佔位符模板。

✅ 正確

```ts
delete: {
  label: (name: string) => `刪除 ${name}`,
  confirmTitle: (name: string) => `確定要刪除「${name}」嗎?`,
},
loading: (what: string) => `${what}載入中…`,
```

```tsx
<IconButton label={t.items.delete.label(item.name)} … />
```

❌ 錯誤

```ts
confirmTitle: '確定要刪除「{name}」嗎?',
// 呼叫端:t.items.delete.confirmTitle.replace('{name}', item.name)
```

**原因:** 不同語言的語序不同(「最多 5 個」/「Up to 5」),函式讓每種語言自己決定變數放哪裡;
參數有型別,少傳一個會編譯失敗。

## 3. `useTranslations` 與 `getTranslations`

**規則:**

- **元件與 hook** 用 `useTranslations()`:它訂閱語言 store,切換語言會重新 render。
- **非元件程式**(純函式、class component、模組層級的程式)用 `getTranslations()`:在被呼叫的
  當下讀語言,不訂閱。
- 純函式優先**由參數接收 `t`**(例:`describeLoadError(error, what, t)`),比在函式內呼叫
  `getTranslations()` 好測。

✅ 正確

```tsx
const LoadErrorPanel: React.FC<LoadErrorPanelProps> = ({ error, what, onRetry }) => {
  const t = useTranslations();
  const copy = describeLoadError(error, what, t);
  // ...
};
```

❌ 錯誤

```tsx
const ItemTable: React.FC<ItemTableProps> = () => {
  const t = getTranslations(); // 元件裡用 getTranslations:切換語言不會更新
};
```

不要在模組頂層把文案存成常數(`const TITLE = zhTW.items.title`):語言切換後它不會變。

## 4. `aria-label` 也進字典

**規則:** `aria-label`、`title`、`placeholder`、Tooltip、`IconButton` 的 `label`、表單驗證訊息、
`message.success` 的文字,全部進字典。

**原因:** 螢幕閱讀器使用者聽到的就是介面;它與畫面文字一樣需要翻譯、一樣由文案負責人審。

✅ `aria-label={t.header.language}`、`label={t.nav.toggleSider}`

❌ `aria-label="Language"`

## 5. 少數允許的字面值

不進字典的只有下列幾類,而且要能說出理由:

| 類別                     | 例子                                                                    | 理由                                                                           |
| ------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 語言名稱                 | `src/i18n/languages.ts` 的 `LANGUAGE_LABELS`(`'繁體中文'`、`'English'`) | 語言名稱永遠以該語言本身呈現:切到英文時,使用者仍要認得出「繁體中文」才切得回來 |
| 後端擁有的資料           | 項目名稱、使用者姓名、後端的 `message`                                  | 不是前端的文案                                                                 |
| 送給後端或用來比對的字串 | 權限代碼、狀態列舉、錯誤 code                                           | 翻譯會讓契約失效                                                               |
| 品牌、產品名             | 由專案決定                                                              | 不翻譯                                                                         |

這類字面值集中在有名字的常數檔(如 `LANGUAGE_LABELS`,型別 `Record<Language, string>` 保證每種
語言都有名稱),檔案註解寫明為什麼不進字典;不散寫在 JSX 裡。

## 6. 兩支守門測試

型別只管「已入典」的條目;下面兩支測試補上型別管不到的部分,都在 `npm test` 裡跑。

### `src/i18n/noBareLiterals.test.ts`

掃 `src/components/` 與 `src/pages/` 的 `.tsx`(不含測試),找出:

- JSX 文字節點(`<Button>新增</Button>`)
- `label=`、`placeholder=`、`title=`、`aria-label=`、`okText=`、`cancelText=` 的字串值

含字母或中日韓文字的就判定為文案,測試失敗。真的需要保留的字面值,加進測試的 `ALLOWED`
(檔案路徑 → 字串清單),**每一條附理由**。

這是保守的啟發式:`label={'新增'}` 這種寫法掃不到,但仍然違規——靠 review 把關。

### `src/i18n/errorCodeCoverage.test.ts`

對 `KNOWN_ERROR_CODES`(`src/types/api/error.ts`)的每一個 code,斷言每種語言的
`errors.byCode[code]` 非空。新增 code 的步驟見 [error-handling.md](./error-handling.md)。

## 7. 測試斷言引用字典

**規則:** 測試裡比對介面文字時,引用字典,不寫死字串:

✅ 正確

```ts
import { zhTW as t } from '@/i18n/zhTW';

expect(await screen.findByText(t.errors.loadFailed(t.items.entity))).toBeInTheDocument();
screen.getByRole('button', { name: t.common.retry });
```

❌ 錯誤

```ts
expect(await screen.findByText('項目載入失敗')).toBeInTheDocument();
```

**原因:** 改一句文案不該讓一批與文案無關的行為測試失敗。`src/test/setup.ts` 每個測試後把語言
重設為 `zh-TW`,所以測試一律引用 `zhTW`。測試資料(mock 回來的項目名稱)不是文案,可以寫死。

## 8. 語言設定

- 語言存在 `useLanguageStore`(persist 到 localStorage),預設 `zh-TW`,不讀瀏覽器語言。
- antd 元件內建文案(分頁、日期選擇器)由 `AppProviders` 的 `ConfigProvider locale` 跟著切換;
  AG Grid 內建文案(篩選選單、分頁器)由 `components/common/DataGrid` 的 `localeText` 跟著切換
  (`@ag-grid-community/locale`);新增語言時三處一起加。
- 新增語言:`stores/useLanguageStore.ts` 的 `LANGUAGES` 加一項 → 新字典檔 `const xx: Translations`
  → `useTranslations.ts` 的 `DICTIONARIES` → `languages.ts` 的 `LANGUAGE_LABELS` → `providers.tsx` 的
  antd locale → `errorCodeCoverage.test.ts`。
- `<html lang>` 由 `AppProviders` 跟著目前語言同步,不需另外處理。
